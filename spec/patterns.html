Patterns Real screens, assembled

What the system feels like in real screens.

Three top-level surfaces, each modeled on a well-loved interface so users land on familiar ground: Home is an AI conversation, DMs is a familiar two-pane chat, Tree is an infinite outline. Everything else is a leaf — a view a user composes on top of their tree.

01 · Home

The start route — a single prompt

Home is a quiet welcome. One input. A handful of suggested verbs. The user types what they want; Twigl decides where it goes in the tree.

One prompt, one tree

No history sidebar, no model picker, no proposal tray on the home route. The point is to start — anywhere the user goes from here, the tree is what they're working in.

The mark sets the tone

The Twiglit leaf on the green disc is the only piece of brand on the page. It anchors the screen the way a logotype anchors a marketing page.

Suggested verbs, not features

The pill prompts read as things a user might already be thinking — what's on my plate, plan my week, capture an idea. They route to the right leaf; users never have to learn which feature to open.

Voice-first ready

The waveform glyph on the composer is the second affordance — tap to talk. On mobile this becomes the dominant input.

One leaf, always. The list and the conversation are the same leaf in two states. Tapping a row replaces the leaf; the back arrow brings the list back. No split view, no master/detail — that's a desktop habit Twiglit doesn't inherit.

People, groups, AI tools — one directory

Humans and AI agents live in the same list. Tools are marked with a AI tool tag in berry, so they're scannable but not loud. A group chat shows N+ in its avatar; AI tools take the berry circle.

Bubbles, the rules

  • Me — green-soft fill, right aligned. Soft enough not to fight the transcript.
  • Them — white with hairline border, left aligned.
  • System — mono caption only; never a coloured bubble.

Twiglit links are first-class

Any bubble can deep-link to a row in the tree with green-underlined text. Clicking jumps to that row. Chats are how people talk about rows; the rows themselves live in the tree.

An outline, infinite

Any twig is the root of its own subtree. Click a twig to focus it; the breadcrumb grows. Hit Esc to climb back up.

Indent & relationship

  • Indent is the only nesting affordance. No chevrons by default.
  • Vertical hairline appears under any twig with children — that's the ancestry guide.
  • Folder icon (green) marks twigs that contain a curated view, not just descendants.

The action bar reacts

Bar 3 is contextual: the verbs change depending on what's selected. When nothing is selected the bar is dimmed but still present, so the chrome stays predictable.

Render leaf

Generated by the AI inside a chat — Claude.ai, the in-app assistant, anywhere else. Same leaf grammar (header, grouped cards, status pills) ships on hosts that aren't Twiglit, so a teammate can act on the rows without leaving their thread.

embed leaf

Same grammar, every leaf

Every leaf opens with a dark header bar — an icon, a title, an optional close. That's the contract that tells you which leaf you're in, and means leaves stack predictably whether they're inside Twiglit or rendered inside someone else's chat.

The tree underneath never moves

Leaves only reshape what you see. A row checked off in the workstation is checked everywhere; a twig moved on the calendar updates everywhere; the issue tracker, the chat, and the render-leaf are all the same rows, lensed.

Render leaves cross the boundary

The last card is rendered inside Claude.ai. Twiglit emits a leaf as a small embed; the host renders it. Users act on their own rows without ever leaving the assistant.

Eventually: user-styled

Leaf bodies can be styled freely (typography, density, color). The header bar, action verbs, and row identity stay system-owned — that's the contract a host can rely on.

05 · Details

The details panel — quiet by default

The hardest surface in the app. It opens whenever you focus a row, so it must support 20 different concerns without feeling like a settings page. Tabs make most of them disappear until asked for.

What's hard about it today

  • 14+ sections stacked at equal weight — no hierarchy.
  • Most fields are empty placeholders eating vertical space.
  • Comments & activity sit below the metadata fold — the thing users come for is the thing they have to scroll for.
  • Section headings ("Multiplied In", "Dependencies", "Twiglits", "Attachments") compete with each other; no visual triage.
  • Tabs at the bottom feel like an afterthought.

What the redesign does

  • Tabs move to the top and default to Comments — the most-touched surface.
  • Metadata collapses to one inline strip — assignee · due · type · repeat. Click any chip to edit.
  • Empty sections vanish. Add affordances become small "+" chips, not stacked headings.
  • Title is large, editable, with the bullet inline. Tap the berry to complete.
  • Body scrolls under a fixed header. Footer keeps ID/created and a kebab — out of the way but reachable.

Layout, top down

  • Top bar (32px). Breadcrumb to remind where you are; close on the right. Nothing else.
  • Title row. The berry bullet doubles as the complete-toggle. Title is editable in place at large size — this is the row's identity.
  • Property strip. A single horizontal line of inline-editable chips. Only properties with values render; the trailing "+" lets the user surface more. Replaces 4–6 stacked form rows.
  • Tabs. Comments default, because that's what users open the panel for 80% of the time. Description for the body, Properties for the long-form metadata (assignee modal, dependencies, multiplied-in, attachments), Activity for the audit log.
  • Body. Scrolls. AI replies (Twigl) get the same bubble register as people — left-aligned, with their identity marked by avatar color and a softer tint. They never look like a form alert.
  • Footer (24px). ID + created timestamp in micro grey. Always visible. Never the focus.

Properties tab — what it holds

Everything that was stacked on the front page lives behind this tab: full assignee picker, dependencies, multiplied-in locations, attachments, repeat rules, custom fields, AI actions ("Start working / Cancel"), extensions. Each gets a dedicated section so they have room to breathe — the front page no longer pays the cost for fields that aren't set.

Empty handling

An empty property doesn't render. Empty Description tab shows a single 80%-faded "Write…" prompt. Empty Activity shows nothing. The user only sees what's there.

AI Actions and Extensions

"Start working" becomes a verb in the kebab — same place as Share, Duplicate, Delete. Extensions (kanban, doc, status, etc.) become small icons on a dedicated row in the Properties tab — not chrome the user has to ignore every time.
